# Backend P0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Implement all 35 P0 operations of the existing contract as a runnable Java/MySQL backend.

**Architecture:** One Spring Boot application, JDBC repositories, Flyway migrations and private immutable image files. Core domain tables remain separate; nested calibration/analysis/annotation snapshots use JSON text, validated against the bundled OpenAPI document. All domain writes and sync events share a transaction and a per-owner scope lock that orders commits.

**Tech Stack:** Existing JDK 21.0.7, Maven 3.9.9, MySQL 8.0.42; Spring Boot 3.5.16. H2 is a test dependency only.

**Spec:** docs/backend/README.md and docs/backend/backend-v1.openapi.json. User approved continuing with the existing tools on 2026-11-03.

## Global Constraints
- No new JDK/Maven/MySQL installation and no global environment changes.
- `/api/v1`, camelCase, Unix milliseconds, direct resources and contract error format.
- P0 first, then P1/P2. Unsupported extensions must not advertise working capabilities.
- Whitelist request fields; enforce ownership at every parent/file/upload access.
- If-Match on resource modifications; persistent transactional idempotency on specified POST operations.
- Immutable image bytes, SHA-256 and actual dimension/type validation before READY.
- Credentials only through environment/local ignored configuration; no default production password or signing secret.

## Review Focus
- Cross-account UUID substitution must never disclose resources or files.
- Refresh replay must revoke the token family even though the HTTP response is an error.
- Concurrent duplicate creates and stale updates must produce one commit and no lost sync changes.
- Snapshot pages must be frozen and tied to the exact event position; cursors bind principal/generation.
- Invalid polygon, invalid measurement and nested merge patches must not preserve stale valid results.

## Execution ledger
- Ruling: Work in the supplied checkout; repository has no initial commit and all contract files are untracked. Creating another worktree cannot preserve this baseline without committing the user's files.
- Ruling: P0 enables personal workspaces only. Hospital identities are not provisioned until P1 membership/grant authorization exists; this prevents treating membership or a role hint as resource authorization.
- Ruling: Use filesystem private object storage initially, behind signed URLs. This satisfies the upload contract on one server; multiple instances require a shared private volume or an object storage adapter.
- Ruling: Reuse existing MySQL without accessing or changing databases until explicit connection credentials are configured. H2 tests do not substitute for the MySQL integration run.
- Ruling: After the user reported forgotten credentials and authorized a new database fallback, start an isolated instance using the existing MySQL 8.0.42 executable on loopback port 3307. Its own data directory and scoped accounts avoid changing the original service/root password. This development instance requires its own backups and startup script.
