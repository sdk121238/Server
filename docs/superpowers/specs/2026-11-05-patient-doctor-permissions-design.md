# 患者、医生权限与患者资料设计

状态：用户已于2026-11-05回复“可以”确认，实施中；实际交付与验证见实现记录。

## 已确认需求

- 使用现有 Java 21、Spring Boot 3.5.16、MySQL 8 环境，不安装新版本。
- 两种业务账号：普通患者与医院医生。
- 普通患者只能访问自己账号拥有的数据。
- 用户已明确确认：所有医生可以查看全部患者；主治医师关联用于筛选“我的患者”。
- 患者增加电话、性别、出生年月、年龄信息。
- 主治医师可不填，选择范围是已创建的医生账号。

## 当前实现与方案选择

现有合同已经声明 PATIENT、HOSPITAL_STAFF，实际认证固定返回 PATIENT，所有资源读取均按 owner_id 限制。患者内容保存在 LONGTEXT payload，姓名等没有独立列；图片字节另存磁盘。Flyway 目前只有 V1，应用有现成的账号预置入口，短信注册和机构管理接口仍未启用。

方案 A：复用已有角色，在 users 保存真实角色；患者新增可检索列，集中实现角色与资源范围校验。保留既有资源 JSON、ETag、离线协议和接口路径，增加医生选择及筛选接口。这是本次建议，变更可以限定在用户提出的两类权限与资料范围。

方案 B：同时实现机构、成员、独立管理员角色和注册审核工作流。能够支持多医院隔离，但会改变“所有医生可看所有患者”的范围，并增加用户未要求的业务。本次不采用。

方案 C：只在前端隐藏数据或根据 requestedRole 授权。不能在后端限制直接请求，不满足权限要求，不采用。

方案 A 的实现建议待本文确认；用户目前确认的是上面的业务可见范围。

## 权限矩阵与账号创建

| 操作 | PATIENT | HOSPITAL_STAFF（医生） |
|---|---|---|
| 查询患者列表和详情 | 本账号数据 | 全部未删除患者 |
| 查询病灶、采集记录和文件信息 | 本账号数据 | 全部患者的对应数据 |
| 申请并下载已完成图片 | 本账号数据 | 全部患者的对应图片 |
| 新建、修改、删除患者及子记录 | 本账号数据 | 本账号数据；暂不开放修改其他账号数据 |
| 给自己的患者选择或取消主治医师 | 允许 | 允许 |
| 修改其他账号的主治医师 | 禁止 | 禁止，本次未授权跨账号修改 |
| 获取可选医生列表 | 已登录可用 | 已登录可用 |
| 账号资料、密码、会话、上传会话、导入计划 | 仅本人 | 仅本人 |

医生对别人的数据为只读，这是基于“查看”需求的实现建议；申请下载 URL 虽为 POST，也属于读取能力。所有医生的可见范围是本应用数据库中的全部患者，不按机构分隔。

角色复用合同值 PATIENT / HOSPITAL_STAFF，界面名称显示“患者 / 医生”。users.role 是授权依据，登录请求的 requestedRole 不授予任何权限。认证查询数据库中的实时角色和状态；角色或状态变化后不能继续利用旧角色访问。

现有账号迁移后全部保留为 PATIENT，禁止自动将 local-owner 或第一个用户升级为医生。提供本机账号维护入口：维护人员通过脚本交互输入账号、显示名、初始密码和角色，创建新的普通账号或医生账号；同名账号不覆盖密码或提升权限。密码输入不回显，不写入版本库，不在控制台打印。医生通过此入口登记后即可出现在可选医生列表中。本次不实现公开自助注册医生，不增加第三种业务管理员角色，也不创建真实医生账号。

## 数据库字段

保留 V1 原样，新增 Flyway 迁移。users 增加 role VARCHAR(32) NOT NULL DEFAULT 'PATIENT'，限制在两种角色中，并建立 (role,status,id) 索引。

patients 增加以下独立列，同时维持与 payload 中对应字段的一致性：

| 数据库列 | API 字段 | 类型 | 含义 |
|---|---|---|---|
| phone_number | phoneNumber | VARCHAR(32) NULL | 联系电话，文本保存，允许国际区号；非空值为可选 + 加 7～15 位数字 |
| gender | gender | VARCHAR(16) NULL | MALE / FEMALE / OTHER / UNKNOWN；旧记录可为空 |
| birth_year_month | birthYearMonth | CHAR(7) NULL | YYYY-MM；不能晚于当前年月 |
| attending_doctor_id | attendingDoctorId | VARCHAR(36) NULL | 关联 users.id，必须是 ACTIVE 的 HOSPITAL_STAFF |

主治关联建立外键和 (attending_doctor_id,deleted_at,id) 索引。外键保证账号存在，业务层保证角色与状态符合要求。新字段可选，原有客户端创建请求继续有效；空白电话规范化为 null，枚举和年月严格验证。

保留原有 birthDate（YYYY-MM-DD）字段，兼容现有客户端。只填写 birthDate 时可推导 birthYearMonth；同时提交两者时必须同月。单独修改出生年月且与既有完整生日冲突时清空旧 birthDate，避免保存矛盾日期；单独清空 birthDate 则保留已有出生年月，单独清空 birthYearMonth 且仍有 birthDate 时返回校验错误，需要两者一起清空。全部规则写入接口说明。

age 作为只读响应字段，类型 integer|null，不建立会随时间变旧的永久年龄列，也不接受前端独立写入。具有 birthDate 时按完整生日计算周岁；只有出生年月时按整月计算：floor((当前年月与出生年月相差月数)/12)，视为生日所在月已到即增岁；缺少出生信息返回 null。计算基准使用 Asia/Shanghai 当日，使用可注入 Clock 便于测试。只接受出生至当前日期/年月，未来生日返回校验错误。

attendingDoctorId=null 表示未指定。响应可以返回 attendingDoctor 摘要（id、displayName），不包含登录账号、密码、令牌或其他患者数据。已被停用或不再是医生的历史关联保留 ID，摘要标记 unavailable；不再接受将新关联指向该账号，患者可以清空或更换关联。关联不会转移患者 owner_id，也不改变所有医生可查看全库的规则。

## 查询和下载

- GET /doctors：登录后分页查询 ACTIVE 医生，响应只包含 id、displayName；支持按显示名搜索。
- GET /patients：患者永远限定 owner_id=本人；医生默认全库，scope=mine 时按 attending_doctor_id=医生本人筛选，scope=all 为全库。患者传任何 scope 都不能扩大本人范围。限制 scope 枚举，拒绝未知值。
- 患者列表按现有 ID 游标分页，scope、搜索词和访问者身份绑定分页令牌，不能跨筛选条件复用。将新增范围筛选放在 SQL 中执行，不能先读全库后分页。
- 病灶、采集和文件详情依据父患者检查读取范围，不能只放开患者列表；普通患者直接猜 ID、改 patientId、fileId 或访问图片都不得读到别人数据。
- 文件元信息与申请下载均检查父患者仍有效、文件已 READY。签名下载票据绑定申请人及文件；下载时重新检查申请人当前角色/状态、文件与患者有效性，医生降权或停用后旧票据失效。
- 上传、修改、删除以及上传签名继续使用所有权校验，与读取权限分开，禁止通过角色通用放行导致越权写入。

## 个人同步与兼容

当前离线快照、增量同步、导入计划继续服务本账号拥有的个人数据。医生的全库查看和“我的患者”通过在线查询接口完成；本次不将全库患者自动下载到医生端，也不把个人同步范围改为全库。相关边界在能力说明与前端对齐文档中明确。

age 和 attendingDoctor 摘要是读取时生成的展示字段，不因每天年龄变化或医生改名增加患者 revision；同步 payload 可保留存储的 birthYearMonth 和 attendingDoctorId，客户端从出生信息计算展示年龄，医生名称从医生目录解析。禁止将读取展示字段带回创建或 PATCH。

角色、患者新列、payload 的旧数据回填需兼容 MySQL 与 H2 测试环境。旧记录已有 birthDate 时回填出生年月，其余新增值为空；不得虚构电话、性别或医生关联。回填不改变旧记录版本与时间，也不制造同步业务修改。读取适配保证已有快照、历史版本和幂等响应不会因缺少新字段而反序列化失败；新请求按新增合同执行。旧幂等响应保持原请求的原响应语义。

## 验证与交付

- 两个患者互相隔离；医生可读双方的患者、病灶、采集、文件与图片；医生不能跨账号写入。
- 主治医师可空，可选医生必须真实存在且有效；普通账号 ID、未知 ID、停用账号均不能作为新主治关联。
- 同时覆盖医生全库和名下筛选、分页、搜索、签名 URL、降权后的会话与票据、父患者删除后的访问。
- 验证电话、性别、出生年月、未来出生日期、月末与生日年龄边界以及年龄只读规则。
- 在含旧数据的迁移测试验证角色默认值、年月回填、payload 一致性、原有外键和原版本保留；执行既有 H2 测试及独立 MySQL 测试库验证，不重建业务库。
- 同步更新实际 OpenAPI 合同、Swagger 示例、前端接口清单、字段字典、测试材料与交接包；保留现有左右分栏 Swagger 页面。
- 业务库升级前生成本地备份并核验可读性；迁移仅增量修改，不删除既有数据；完成后重启后端并验证版本及关键读取。

## 本文需确认的实现建议

1. 医生跨账号只读；跨账号修改与管理暂不开放。
2. 新增资料字段属于患者档案，不强制重复存入登录账号；年龄由出生信息计算，精度规则如上。
3. 医生账号先通过本机维护入口创建，不开放公开自助注册医生。
4. 医生全库读取采用在线接口，个人离线同步范围维持本人拥有的数据。
